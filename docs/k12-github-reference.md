# 中小学辅助学习系统 · GitHub 调研与借鉴记录

> 图形题与老师作业导入的进一步调研见 [homework-import-and-figures.md](homework-import-and-figures.md)。

调研时间：2026-11-03。目标是在 GitHub 上寻找可参考的中小学（K-12）辅助学习系统，提炼适合本项目的学习机制，并说明哪些已经落地、哪些只作为后续方向。

> 说明：下面的星标、许可证和活跃度来自调研当天的 GitHub API。各项目的功能以其 README 为准；本项目只借鉴交互与学习机制，不复制它们的题库、文案、图片或代码。

## 1. 调研范围与方法

在 GitHub 上按 `K-12 learning`、`topic:k12`、`topic:primary-school`、`中小学`、`小学 数学 练习`、`题库 错题`、`口算` 等关键词检索，再结合已知的开源教育项目核对。筛选标准：

1. 与中小学学习或练习直接相关，或提供了可迁移的学习机制；
2. 有公开源码和明确许可证；
3. 仍在维护，能看清产品结构；
4. 优先本地优先、无需后端、适合家庭使用的项目。

### 重点项目的具体观察

- **Kolibri / Oppia**：都把“练习—反馈—掌握”做成闭环，并保留学习记录供复盘。它们不追求一次答对，而是让学习者反复练到掌握。这适合本项目的“错题重练 + 掌握标记”。
- **cn-math-taxonomy**：把知识点组织成有向先修图，答错时不是简单重复原题，而是沿先修边向下诊断。本项目当前只有一个年级的题库，暂时无法做完整图谱，但可以先按“知识点”聚合错题，优先练错得最多的知识点。
- **congcong-school**：把内容按教材单元铺成学习路径，并用 XP、连续学习等轻量激励维持习惯。它的全科、多年级内容量远超本项目，不适合整体照搬。
- **shiyi-math-practice / zx-study**：和本项目最接近——纯前端或本地优先、家庭使用、错题本 + 统计 + 每日练习。它们验证了“本地 localStorage + 错题本 + 掌握状态”这套轻量方案的可行性。
- **math-mastery**：参数化出题能解决题库有限、重复刷题的问题。但它没有声明许可证，且自动生成题需要严格的正确性校验，本次只作为后续方向记录，没有复制代码。

## 3. 本次落地的借鉴点

结合本项目“单页静态、无后端、每次 10 题”的现状，选择了三个成本低、对学习闭环帮助最大的机制：

1. **持久错题本**（参考 shiyi-math-practice、zx-study）
   - 答错自动写入 `localStorage`，记录科目、知识点、错误次数、连续答对次数；
   - 支持跨局、跨天保留，不再只停留在单次结果页。

2. **掌握状态与错题重练**（参考 Kolibri / Oppia 的掌握式学习，shiyi 的“答对即掌握”）
   - 同一道错题连续答对 2 次后标记为掌握，之后不再出现在待复习列表；
   - 再次答错会重置连对次数并回到错题本；
   - “错题重练”按错误次数多、最近未复习的题优先抽取，最多 10 题。

3. **学习档案**（参考 zx-study 的学习统计与连续学习天数）
   - 首页展示累计答题、总正确率、连续学习天数、待复习错题；
   - 按知识点汇总待复习错题，形成“薄弱知识点”提示；
   - 数据仍然只保存在当前浏览器，不上传服务器。

没有采纳的部分：

- **知识图谱与前置诊断**：需要多年级、跨学段题库和教师审核过的先修关系，本项目题库只有五年级期中范围，硬做会变成伪诊断；
- **参数化出题**：需要为每个题型写生成器和校验器，且 math-mastery 未声明许可证，暂不引入；
- **全科多年级内容库**：属于内容建设，不是一次交互改造能完成的范围；
- **账号、班级、教师后台**：与当前“双击即玩、本地保存”的产品形态冲突。

## 4. 后续可继续借鉴的方向

1. 增加“每日一练”和更完整的间隔重复调度（参考 Anki 的到期复习，而不是只按错误次数排序）。
2. 为数学题引入参数化生成，但必须配套答案校验和题库自检（参考 math-mastery 的生成器结构）。
3. 把知识点整理成先修关系，做“答错后回溯基础知识点”的诊断（参考 cn-math-taxonomy）。
4. 增加错题打印/导出，方便线下复盘（参考 shiyi-math-practice、zx-study）。
5. 语文扩展汉字笔顺演示（参考 hanzi-writer）。
